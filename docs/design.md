# TODO App 設計書

作成日: 2026-06-24

## 1. 目的

このアプリは、AI開発の技術検証として TODO アプリを段階的に構築するための題材である。

検証観点は AIDD と AIAD の比較であり、本プロジェクトでは AIAD 側の対応として、AIに実装を依頼しながらも、設計・テスト・レビュー・記録を明示的に残す進め方を採用する。

## 2. 対象ユーザ

一般ユーザを対象とする。専門的なプロジェクト管理ツールではなく、日常のタスク整理と実行を支援する汎用TODOアプリとして設計する。

## 3. 解決したい課題

- タスクを登録して満足してしまい、実行に移れない。
- 優先順位を決められず、どのタスクから着手するべきか分からない。
- 期限切れタスクに気づけず、対応が遅れる。

## 4. 開発フェーズ

### Phase 1: 基本TODO

最小限のTODO管理機能を提供する。

- TODO登録
- 一覧表示
- 編集
- 削除
- 完了
- 期限設定
- 今日やるTODO表示
- カテゴリ設定
- 検索

### Phase 2: 少し複雑な機能

タスクの構造化と整理機能を追加する。

- タスクの階層化
  - 親タスク
  - 子タスク
- 進捗バー
  - タスクごとに手入力した進捗率を表示する。
  - 進捗率は 0% から 100% の整数として扱う。
  - 親タスクも子タスク完了率から自動計算せず、手入力した進捗率を表示する。
  - 完了操作を行った場合は、進捗率を 100% に更新する。
- 並べ替え
  - 期限が近い順
  - 優先度順
  - 作成日順
  - 未完了優先

### Phase 3: 独自価値の機能

課題「タスクを登録して満足してしまう」を抑止するため、単なる登録数の増加ではなく、実行への移行を促す機能を設計する。

#### 検討した機能案

1. 着手コミット機能
   - タスク登録時に「最初の一歩」を必須または推奨入力にする。
   - 例: 「資料を作る」ではなく「既存資料を5分見る」を登録する。

2. 今日やる上限機能
   - 今日やるTODOを選びすぎないように、1日あたりの選択数に目安を設ける。
   - 初期値は 3 件とし、設定で変更できるようにする。

3. 未着手タスク警告
   - 登録後、一定期間ステータスが未着手のタスクを目立たせる。
   - 期限切れとは別に「登録しただけ」の状態を可視化する。

4. 着手ログ
   - タスクの「開始」操作を記録する。
   - 完了だけでなく、着手したかどうかを管理できるようにする。

5. 分解提案
   - 大きすぎるタスクに対して、子タスクへの分解を促す。
   - 初期実装ではAI提案ではなく、文字数や期限までの日数をもとにしたルールベースの案内に留める。

#### Phase 3 で採用する機能

Phase 3 では、以下の3つを組み合わせて実装する。

- 最初の一歩
- 今日やる上限
- 未着手タスク警告

理由:

- 「登録して満足」を防ぐには、登録時点で実行可能な次アクションに落とす必要がある。
- 今日やるタスクを絞ることで、優先順位を決められない課題にも対応できる。
- 未着手状態を可視化することで、期限切れになる前に気づける。

## 5. 画面構成

一覧画面 + モーダル登録の最小構成とする。

### 一覧画面

主な構成:

- ヘッダー
  - アプリ名
  - 新規登録ボタン
- 今日やるTODOエリア
  - 今日やる対象の未完了タスク
  - 今日やる件数の上限表示
  - 今日やる上限と未着手警告日数を変更する設定ボタン
  - 設定ボタン押下で設定モーダルを表示する
- フィルタ・検索エリア
  - キーワード検索
    - 検索対象はタスクのタイトル、説明、最初の一歩。
  - カテゴリ絞り込み
  - 完了状態フィルタ
  - 今日やるTODO絞り込み
  - 並べ替え
  - 親タスクがフィルタ対象外で子タスクのみが表示される場合も、子タスクは親タスク扱いにせず、子タスクとして表示する。
  - 親タスクがフィルタ対象外でも、子タスクには親タスク名を表示する。
- タスク一覧
  - タスク名
  - 作成日
  - 期限
  - カテゴリ
  - 優先度
  - ステータス
- 親子関係
- 進捗バー
  - 進捗率
- 編集、削除、完了、開始操作

### 登録・編集モーダル

登録と編集は同じモーダルを使う。

主な入力項目:

- タイトル
- 説明
- 期限
- カテゴリ
- 優先度
- 今日やる対象か
- 親タスク
- 最初の一歩
- 進捗率

## 6. データ項目

### Task

| 項目 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| id | string | 必須 | UUID |
| title | string | 必須 | タスク名 |
| description | string | 任意 | 詳細説明 |
| status | enum | 必須 | `todo`, `in_progress`, `done` |
| priority | enum | 必須 | `low`, `medium`, `high` |
| dueDate | date | 任意 | 期限 |
| categoryId | string | 任意 | カテゴリID |
| parentTaskId | string | 任意 | 親タスクID |
| firstAction | string | 任意 | 最初の一歩 |
| progress | number | 必須 | 手入力する進捗率。0から100の整数 |
| isToday | boolean | 必須 | 今日やるTODOか |
| startedAt | datetime | 任意 | 着手日時 |
| completedAt | datetime | 任意 | 完了日時 |
| createdAt | datetime | 必須 | 作成日時 |
| updatedAt | datetime | 必須 | 更新日時 |

| 項目 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |

| color | string | 必須 | 表示色 |
| createdAt | datetime | 必須 | 作成日時 |
| updatedAt | datetime | 必須 | 更新日時 |

| 項目 | 型 | 必須 | 説明 |

## 7. API設計

フロントエンドとバックエンドを分離するため、バックエンドはREST APIを提供する。

### Tasks

- `GET /api/tasks`
  - タスク一覧取得
  - クエリ: `q`, `categoryId`, `status`, `isToday`, `sort`
  - `q` はタイトル、説明、最初の一歩を対象に部分一致検索する。
  - レスポンス: `parentTaskId` があるタスクには表示用の `parentTaskTitle` を含める。
- `POST /api/tasks`
  - タスク登録
- `GET /api/tasks/:id`
  - タスク詳細取得
- `PUT /api/tasks/:id`
  - タスク更新
- `DELETE /api/tasks/:id`
  - タスク削除
- `PATCH /api/tasks/:id/complete`
  - 完了状態へ更新
- `PATCH /api/tasks/:id/start`
  - 着手状態へ更新

### Categories

- `GET /api/categories`
- `POST /api/categories`
- `PUT /api/categories/:id`
- `DELETE /api/categories/:id`

### Settings

- `GET /api/settings`
- `PUT /api/settings`

## 8. バリデーション

- タイトルは必須、最大100文字。
- 説明は最大1000文字。
- 期限は任意。ただし過去日も登録可能とし、一覧で期限切れとして表示する。
- 親タスクに自分自身や子孫タスクは指定できない。
- 進捗率は 0 から 100 の整数。
- 今日やるTODOが上限を超える場合は警告を表示する。ただし登録自体はブロックしない。
- 完了済みタスクの子タスクが未完了の場合は、親タスク完了時に確認を出す。

### フロントエンド

  - 今日やるTODO表示

  - 親子タスクと進捗バー

### バックエンド

- APIテスト
  - CRUD
  - 検索
  - 並べ替え
  - 親子関係バリデーション
- 単体テスト
  - 進捗率計算
  - 未着手警告判定
  - 今日やる上限判定
